# Learning Gym retrospectives

This directory gives learners and AI tutors enough context to review the teaching design from the public repository. The course asks a learner to predict an outcome, run or verify a small example, change one variable, and explain the result. An AI tutor can supply the scaffold and checks. The learner owns the prediction, intervention choice, and explanation.

## Start a review

1. Identify the capability the learner wanted to gain and the evidence that would count.
2. Compare the actual task, what the tutor supplied, and what the learner could do independently. Separate prepared materials, learner answers, and verified results.
3. Record plausible alternatives before inferring why a session felt effective or frustrating. Prior knowledge, practical relevance, prompt clarity, and the feedback loop can all differ.
4. Propose a small check that keeps the context stable and has a visible finish condition. Treat the check as a proposal until it has been tried.

For the first investigation, see [Learning robotics RL with an AI tutor](rl-learning.md). For the overall workflow, see [learning modes](../learning-modes.md) and the [course map](../curriculum.md).

## Reading this initial export

Learning Gym started in a larger robotics repository. This public snapshot preserves course materials, browser reading editions, toy scripts, and recorded learning examples. Historical mentions of company plans, private code, and runs provide context. Where the underlying evidence is unavailable to public readers, the source is marked as private. Use the standalone toy checks and public papers for independently reproducible comparisons.

For feedback from a human reading the TD3-first handout, see [TD3-first learner feedback](td3-first-lesson-feedback.md). It records both what helped and what the first revision omitted.
