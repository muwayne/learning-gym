## ① 预测（任务书发布后锁定）

### Arm G · execution horizon（看结果前锁定）

- `E: 1 → 4 → 16`：预测 XY-support exits **更多且更早**；SR **逐步下降**。
- 关系判断：初答 `threshold-like`，在运行前主动收回并修订为 **偏 linear / gradual change**。
- Wayne mechanism：每个额外 open-loop execution step 都增加偏离机会；离开 XY-support 后，偏差可能进一步加速。
- 精度边界：`first XY-support exit` 的 τ 只是 observer-side diagnostic，不会触发 environment 或 policy 切换；若 exit 后误差加速，那是 policy extrapolation / closed-loop dynamics 的经验现象，不能把 crossing 本身写成原因。SR 受 corridor wall 与终点的离散 success predicate 影响，即使 continuous deviation 渐变，aggregate SR 也可能呈非线性。

**结果与判定**：

| E | XY-support exits | Mean first exit（conditional） | Return rate given exit | SR |
|---:|---:|---:|---:|---:|
| 1 | 2/20 | 44.5 | 2/2 | 20/20 |
| 4 | 16/20 | 69.0 | 15/16 | 20/20 |
| 16 | 20/20 | 30.75 | 10/20 | 7/20 |

- “exits 更多”命中；“更早”部分命中，仅 E16 明显提前；“SR 下降”端点方向命中，但不是逐步下降。
- 运行前修订的偏 linear / gradual prediction 未命中；测试网格上呈 E1/E4 plateau、E16 sharp degradation，初始后收回的 `threshold-like` 直觉反而更贴近结果。
- Paired case 对账：E16 未 return 的 10 条为 0/10 success；return 的 10 条为 7/10 success。E4 即使 16/20 exit 仍 20/20 success，证明 support exit 本身不能预测 task failure。
- Wayne Explain：还必须看 **return rate**。精确版：结合 exit 时机、`return-to-support rate` 与 wall/timeout；接近终点才 exit 的 trajectory 即使未 return 也可能成功。

### Arm H · recovery data

- `E16 SR`：预测 **升高**。
- 原 clean expert holdout loss：预测 **升高**。
- Wayne mechanism：加入 recovery states 后，固定 sampling / optimization budget 中原 clean data 被 sample 得更少。
- 精度补充：runner 不是把 baseline 文件与 recovery 文件简单混合，而是重新 collection；准确说法是 clean-region states 在新 training distribution 中的相对 exposure 下降。预测的 tradeoff 是 recovery coverage 改善 closed loop，同时 nominal expert-state fitting 可能退化。

**结果与判定**：

- Fixed clean holdout loss：`1.4767e-3 → 1.4882e-3`（`+0.78%`）；“升高”方向命中，但实际应表述为基本保持、轻微恶化，clean holdout cost 很小。
- Paired E16 SR：`7/20 → 13/20`（`+30pp`）；7 条 failure→success、1 条 success→failure，方向命中。
- Evidence strength：G/H Wilson intervals 仍重叠，paired two-sided exact McNemar `p≈0.070`；Wayne 初判“recovery data 已被证明有效”过强。准确表述是：对这 20 个固定 cases 有效，并提供 general improvement 的 directional positive evidence，尚未证明稳定泛化。
- E16 return rate（相对各自 training support）`50% → 78.9%` 仅作 descriptive evidence，因为 Arm H 扩展了 support reference，跨 Arm 不是严格同口径。
- Action health：E16 clipping fraction `0.26% → 0.82%`；Wayne 追问该指标含义，进入 Contract 补课。

## ④ 实验与干预（P-T-I-E）

- **实现路径**：[t0_gap.py](../code/t0/t0_gap.py)；输出留在 `/private/tmp/gap-wayne-s03-{baseline,G,H}`，不作为持久证据入库。
- **Arm F · instrumentation**：baseline 的 train / holdout loss 为 `1.33e-3 / 1.48e-3`；固定 clean holdout 的 chunk tail H8 MSE 比 early H8 高约 17%。E1 为 `20/20 SR`；4 条 XY-support exit 全部 return 且成功，说明 support exit 只表示 novelty，不等于 task failure。
- **Arm G · execution horizon**：只改变执行时重新 observe 的频率，同一 checkpoint、同一逐 case seed 与 initial state 比较 E1/E4/E16。结果是 `20/20 → 20/20 → 7/20 SR`；E16 的 10 条 non-return trajectories 为 `0/10 success`，return trajectories 为 `7/10 success`。E4 的 late exit 仍可成功，故 return rate 还需结合 exit timing 与 termination predicate。
- **Arm H · recovery data**：训练 collection 加入 perturbation + expert recovery action，其余主要预算与 Arm G 对齐。fixed clean holdout loss 仅增加 `0.78%`，paired E16 SR 从 `7/20` 升至 `13/20`；paired flips 为 7 条 failure→success、1 条 success→failure。结果提供 directional positive evidence，但 Wilson interval 重叠且 exact McNemar `p≈0.070`，不能写成稳定泛化已获证明。
- **Contract instrumentation 修正**：原 runner 在同一 E 内复用 RNG stream，trajectory 长度变化会让后续 cases 错位。现改为逐 case 固定 seed，并把 seed / initial state 写入 summary；smoke test 验证 E1/E4/E16 的配对一致。action clipping 记录 raw 与 executed action 的差异，其中 H-E16 clipping fraction 为 `0.82%`，属于 Contract warning，不自动等于 failure cause。
- **Surprise**：Wayne 在看结果前主动把 `threshold-like` 改押 `linear / gradual`；实测却是 E1/E4 plateau、E16 sharp degradation。continuous deviation 可以逐步积累，但 corridor success predicate、recovery basin 与 feedback interval 会让 aggregate SR 呈非线性。

## AI Claim Audit

| Claim | Verdict | Evidence |
|---|---|---|
| runner 的 XY nearest-training-state threshold crossing 可直接称为 `first divergence` | **Conceptually wrong** | 实现只计算 `(x,y)` 到 training samples 的最近距离，未比较 reference trajectory，也忽略 policy observation 中的 heading θ；已改称 `first XY-support exit` |
| `expert-action replay failed` 足以唯一归类到一个 debugging layer | **Plausible but vague / under-specified** | failure 可能指 trajectory 已物理偏离（Contract），也可能指任务完成但 scorer 仍报失败（Evaluation）；必须先定义 failure predicate |
| runner 对每个 E 只重置一次共享 RNG，就能保证全部 rollout cases paired | **Conceptually wrong** | episode 长度随 E 改变时会消耗不同数量的 random draws，使后续 case 的 initial state / wind 错位；已改为每个 case 使用独立固定 seed，并在 summary 记录 seed 与 initial state，smoke 验证 E1/E4/E16 逐 case 相同 |

## ⑤ 固化

- **Revised mental model**：offline loss 只衡量固定 expert-distribution anchors 上的 action fitting；execution horizon / controller contract 决定 feedback 多久不回来，误差会产生新的 policy-induced states，而 SR 还取决于这些 states 上的 recovery capability 与 task success predicate，所以低 loss 既不保证高 SR，也不能单独定位 failure cause。
- **Open/closed-loop 助记**：`Open-loop：后果不回来；Closed-loop：后果回来参与下一次决策。` H16/E16 在 chunk 内 open-loop、chunk 间及 episode 整体 closed-loop。
- **G2.0 应用作业**：static PASS 与 offline improvement 能排除一批粗接口故障和 classical overfitting 叙事，但不能把 recovery failure 从 plausible hypothesis 升格为 established cause。Wayne 正确判为 `Untested`，并指出所缺的 `first divergence` 与 divergence-state expert takeover evidence。
- **ledger 已追加**：Arm G 三条、Arm H 两条，共 5 条（命中 2 · 部分 2 · 未命中 1）。
- **下一个最小 falsification**：保存首次 divergence 的 simulator state；固定 reset / RNG，从该 state 分别运行 policy continuation 与 expert takeover，并记录 rejoin-to-support、task predicates 与最终 SR。若 expert 同样无法恢复，便削弱“policy 缺少 recovery capability”这个解释，并把排查转向 state recoverability、Contract 或 Evaluation。
