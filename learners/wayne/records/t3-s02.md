# T3·S02 · TD3 update 走读 — Wayne

本次在 [TD3 讲义](../../../modules/t3-sim-to-rl/td3/README.md) 阅读后，用滑块的两条 replay 经验做问答和开卷伪代码复述。目的是跟清一次 update 的数据与参数走向。导师提供了 replay 表、题面和伪代码骨架。

| 检查点 | 学员作答与现场补充 |
| --- | --- |
| 两种 TD target | 给齐 replay 数据、terminal flag 和估值后，学员写出第一条 `−0.1 + 0.9 × 0.18`、第二条 `1 + 0`，并用 `min` 给出的较低估值计算第一条。这里使用题面舍入值。 |
| Critic regression | 学员指出两个 online Critics 都用原来的 `S` 和实际执行的 `A`。导师补齐两者各自的预测都与同一个 TD target 比较。首次解释单条预测在 batch 更新后为何可能反向时，学员猜测与扰动有关，导师补讲共享参数会合并整批梯度。 |
| Actor 的动作与梯度 | 学员找出 `Q1(S, Actor(S_next))` 的 state 错配，将 Actor 的输入改回 `S`，并选 `0.2` 作为当前应评分的 action。学员也指出冻结 `Q1` 参数时梯度仍能到 action，整段放进 `no_grad` 会切断该路径。 |
| Delay、同步与端到端复述 | 在第二次 update 的题面下，学员正确区分 online Actor 走 optimizer 和三个 target networks 用 `τ` 同步。随后能按骨架串起各 block。导师纠正 TD target 的直接输入包括 `R` 与 `terminated`，并补齐 `critic_updates % policy_delay == 0` 的周期条件。 |
| `min` 的对照范围 | 首答将换掉 `min` 理解为两个更新都只用 `Q1`。导师拆开解释：固定同一条 replay 和 `A_next` 时，直接改的是两路 Critic 共用的 TD target。要判断实际控制表现，需要另外训练和评测。 |
