## 本课地图与当前理解

- 主链：`token IDs → hidden states → next-token logits → cross-entropy → gradients → updated parameters → autoregressive generation`；
- `x=data[i:i+T]`，`y=data[i+1:i+T+1]`；`T` 是 window length，不是 absolute end index；
- `token_embedding(x)` 为 `(B,T,D)`；position table 是 `(block_size,D)`，当前 lookup 为 `(T,D)`，以 `(1,T,D)` 语义沿 batch broadcast；
- `lm_head: D→V` 只改变最后一维，`(B,T,D)→(B,T,V)`；flatten 后是 `B×T` 道各有 `V` classes 的 next-token questions；
- teacher-forced loss 使用 ground-truth prefixes；autoregressive generation 使用 model-induced prefixes，因此单步 error 会改变后续 input distribution；
- `zero_grad → forward → backward → step`；不清空 `.grad` 会得到非预期的跨 batch gradient accumulation。

## Prediction（完整 checkpoint 设计发布后锁定）

- **P1 · single-batch overfit**：400 个 fixed-batch steps 后 loss 会低于 `0.10` → **命中**（`0.0113`）。
- **Mechanism（磨亮）**：同一个 shifted `(x,y)` batch 被反复呈现，模型容量足够且 parameter/gradient/optimizer path 已连接时，可以记住这些 conditional next-token mappings。
- **Falsifier**：step 400 的 loss 仍不低于 `0.10`。
- **解释边界**：若失败，只能说明 data/target、forward、gradient、optimizer 或 capacity 至少一环有问题；不能在 instrumentation 前直接归因于某个“传递函数”。即使成功，也不单独证明 objective semantics、causal mask 或 generalization 正确。
- **P2 · context-match A/B probe（运行前锁定，已命中）**：正确 next token 是空格；完整复现 fixed row 7 context 的 `B=".\nthe small robot"`，应有 `P(" " | B) > P(" " | A)`，其中 `A="the small robot"` 从 local position 0 开始。结果：A 的 top-1 是 `h`（`0.9987`），空格 probability 约为 `0`、rank `16`；B 的 top-1 是空格（`0.9997`）、rank `1`。
- **P2 解释边界**：A/B 同时改变了 absolute positions 和 preceding tokens `".\n"`，所以它强力证明 exact training-context match 的影响，却不能单独识别两种因素各自的贡献。probe 使用 deterministic distribution，不受 sampled rollout 影响。
- **P3 · objective control（运行前锁定）**：`y=x` 的 own-objective loss 应比 next-token objective 更容易、更快下降，但两者的 final loss 未必显著分开、也不能跨 objective 直接公平比较；在统一的 true next-token validation 上，`y=x` 应显著更差。generated sample 仅作 qualitative sanity check，不使用主观的“generation quality”作为评分指标。

## Checkpoint 2 · proper baseline × objective control（已运行）

- Data contract：先按 sentence 划分 train/validation，再分别重复；每个 optimizer step 从 train corpus 随机采样新 windows，避免 fixed-batch memorization，也避免相同句子副本跨 split 泄漏。
- 公平对照：两条 arms 使用相同 initialization、batch starts、model config、optimizer 与 800 steps；唯一 intervention 是 `next-token targets` 对 `y=x`。
- 统一评分：own-objective train loss 只说明各自 objective 是否被优化；正式 task contract 使用正确 shifted targets 计算 true next-token train/validation loss 与 validation token accuracy。
