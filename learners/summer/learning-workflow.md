# Summer · 从可视化预习到实现回顾的学习流程

> 授课安排 · 2026-09-14 · 根据授课人本次明确要求建立；适用于 Summer 后续课程，A1·S01–S03 是首个落地案例。
> [HTML 阅读版](learning-workflow.html)。这是学习方式与待执行案例，不是已完成记录，不替代 Summer 的能力自述。统一课次与 Pass gates 仍见 [learning modes](../../learning-modes.md)。

## 1 · 固定主线，按小闭环推进

**充分的可视化教学材料 → 知识点问答 → 少量手动计算 → 口述编程 → 运行与 debug → 改动判断 → 整体回顾。**

先把本课目标、概念地图、必需前导知识、已算好的例子和 shape 交给 Summer，再开始提问。先读完整课程地图；每次 session 从其中一个知识点或小组开始，不在问答时突然引入未讲过的前提。讲解阶段不打断学员逐个报乘积；进入练习阶段，再明确切换为少量手算。

这个顺序是 Summer 的典型学习路径，不要求一次坐完，也不要求每个知识点都运行一次完整训练。问答卡住就回读对应解释，公式到代码卡住就缩小输入；已有可核验证据时可短 reactivation 后继续。默认先阅读并建立 Understand，再沿该流程进入 Implement；是否达到 Improve 取决于正式证据，不把一次 debug 自动记为 Improve。

| 阶段 | Summer 做什么 | 讲师 / AI 做什么 | 自然停止点与留痕 |
|---|---|---|---|
| 可视化预习 | 看地图、例子、函数曲线、shape；指出不明白的词 | 先补依赖概念，给完整 worked example；每轮一个核心知识点 | 能指出这一步的输入、输出和作用；阅读本身不记通过 |
| 知识点问答 | 用自己的话作简短解释 | 一次问一个有上下文的问题；回答后再反馈，不连续堆题 | 留一条学员原答与修订理解 |
| 少量手算 | 算 1–3 个有代表性的格子或一步更新，并写轴名 | 给清楚的数值、目标与舍入规则；反馈维度/机制错误 | 算清一小步即可，不把整张矩阵当体力作业 |
| 口述编程 | 说清输入、操作顺序、参数、轴与预期 shape | 把学员决定转写成代码，指出含糊处；不默默替学员补核心逻辑 | 每个核心操作能追溯到学员口述；先有预期再运行 |
| 运行与 debug | 读实际输出、断言与报错，提出原因并选择检查 | 执行已口述实现，提供 shape/数值/日志；把现象与解释分开 | 一次具体 failure 被定位，并有最小验证；无故障时验证边界条件 |
| 改动判断 | 先写预测与推翻条件，一次只改一个变量，再比较结果 | 固定输入、seed、评测口径，运行对照；检查是否引入回归 | 至少一条可判定 prediction 和结果解释；不见结果先写答案 |
| 整体回顾 | 复述完整数据流，解释原误区与修正，说明证据边界 | 按统一 gates 核查缺口，标出下一入口 | 留 revised mental model、实现路径、运行证据与未解问题 |

**口述编程的所有权：** 它沿用学员选择操作、AI 转写的“口述驾驶”。AI 可以搭 harness 与 assertions；核心公式、轴、mask 和目标偏移由 Summer 决定。若 AI 先展示了完整答案，只能记为示范，需换一个小输入或迁移情境重新取得学员自己的解释与实现证据。不得把 AI 自动补全的完整解答记为独立掌握。

## 2 · A1·S01–S03 的对应安排

先读 [HTML 入门讲义](../../modules/a1-transformer/s01-s03-primer.html) 与 [三课汇总课表](../../modules/a1-transformer/s01-s03-overview.html)。讲义的 word-level 例子便于理解；进入正式 S03 时仍使用原 character-level 实验，先展示切分、真实 corpus、windows 和 targets，再运行。

下表是问答入口索引，不要一次把全部问题发给学员。每个问题先带上对应讲义上下文；手算从同一课中挑 1–3 项，不要求每行都算。

| 讲义知识点 | 简单问答入口 | 可选的小手算 / 口述衔接 |
|---|---|---|
| 1 Token / ID | `cat`、ID 1、embedding 有什么区别？ | 按给定词表写一句话的 IDs |
| 2 Shape | `(B,T,D)` 三个轴各数什么？ | 给两条三词输入标轴 |
| 3 Dot / matmul | Q 的一行与 Kᵀ 的一列对应谁？ | 算 `3×2 @ 2×3` 的一个格子 |
| 4 Weighted sum | 为什么输出不是简单挑一个 V？ | 算两向量的加权和 |
| 5 Activation | ReLU 与 LeakyReLU 在负输入处怎样不同？ | 输入 -2 时算两个输出；口述逐元素操作 |
| 6 Softmax | 它为什么按一行归一化？ | 两个相同分数对应什么分配？ |
| 7 Sigmoid / BCE | 哪一个转换概率，哪一个还需要标签？ | p=0.8，比较 y=1 与 y=0 的 loss 大小 |
| 8 Logit / log-prob | 负 log-prob 是否表示“负概率”？ | 给定 p，区分 log p 与 -log p；可用计算器 |
| 9 QKV 与 shape | W_Q 和 Q 分别是什么？V 与 V_vocab 呢？ | 写 X→Q/K/V 的 shape |
| 10 QKᵀ 分数 | 为什么输出是位置×位置？ | 算一个 Query 对两个 Key 的分数 |
| 11 缩放 | 分母用匹配维度还是 token 数？ | 写出 d_k=2 时的缩放因子 |
| 12 PV | 哪个轴在这次乘法中被求和？ | 写 `(T,T) @ (T,d_v)` 的输出 shape |
| 13 Mask | 把禁止项的 score 乘 0 为什么不够？ | 说明 e⁰ 对分母的影响 |
| 14 Causal | 输入有当前词，为什么不算偷看答案？ | 写 `the cat sat .` 的 x/y 对齐 |
| 15 Multi-head | reshape 为什么不能替代交换 T/H？ | 追踪一个 `(b,t,h,r)` 元素的归属 |
| 16 Residual | 相加的两条分支为什么要同 shape？ | 算一个二维残差更新 |
| 17 LayerNorm | 它和 gradient norm 在处理什么不同对象？ | `[1,3]` 的均值和方差 |
| 18 FFN / block | 哪一部分跨 token，哪一部分逐 token？ | 口述两个 Pre-LN 子层的顺序 |
| 19 Embedding / batch | 一条样本会不会读到另一条样本？ | 写 IDs→embedding 的 shape |
| 20 LM head | D 什么时候映射到 V_vocab？ | 写 `(2,3,4) @ (4,6)` 的结果 shape |
| 21 Targets | `y=x` 优化得好能说明会续写吗？ | 对四个 token 做一次 target shift |
| 22 Loss / gradient | loss、grad norm、update norm 各说明什么？ | g=[3,4]，算 norm 与阈值 1 的裁剪结果 |
| 23 Two loops | backward 与 step 谁计算梯度、谁更新参数？ | 口述训练与生成循环差异 |
| 24 Evidence | single-batch overfit 能证明泛化吗？ | 指明 train / held-out / true target 各自的证据 |

## 3 · 第一例：S01 的小闭环怎样实际开展

**状态：待执行示例；下面没有 Summer 的实际回答或运行结果。**

先回读知识点 3、9–13。题面一次给全：有三个输入位置；Q 和 K 都为 `(3,2)`；这次只计算未缩放分数，不加 mask、不做 softmax。给定：

```text
Q = [[1,0], [0,1], [1,1]]
K = [[1,1], [2,0], [0,2]]
```

1. **问答：** 先让 Summer 解释 `Q @ K.T` 的行/列对应谁，输出 shape 是什么；解释后再给反馈。
2. **手算：** 只算第 1 个 Query 与第 2 个 Key 的 dot product，再算第 3 个 Query 的一行。无需把九格逐个报一遍。
3. **口述编程：** Summer 说出输入 shape、转置哪两个轴、用矩阵乘还是逐元素乘、预期输出；AI 按口述转写，先打印 shape 再计算数值。
4. **运行/debug：** 对比手算与实际输出。若结果不对，先定位“轴/运算/数值”中的哪一类；若直接跑通，检查交换两个 Key 行时输出哪部分应交换。AI 不为了凑环节伪造报错。
5. **改动判断：** 固定 Q，只交换 K 的前两行。先写“哪些输出会怎样变、什么结果能推翻预测”，再运行对照。随后可衔接 scaled softmax 与 PV，或到此结束 session。
6. **回顾：** Summer 用一句话区分 dot product 与 matrix multiplication，再解释 QKᵀ 的两轴为什么都是位置。保存口述决策、实际输出、预测判定和修正理解。

## 4 · 怎样记录，怎样恢复下一次 session

在实际课次记录中保留：**阅读范围 → 学员原答 → 小手算 → 口述决定与实现路径 → 原始现象 → 假设/检查 → 改动前预测 → 实际对照 → 回顾与下一入口**。能够复用现有 [session-log 模板](../../templates/session-log.md) 的字段就直接复用，不复制第二份预测账本。

只有实际发生的 prediction 才追加进 Summer 的 ledger；只有满足正式 gates 的 evidence 才更新 progress。无运行结果时写“待执行”，不要把讲义参考答案或测试脚本输出写成学员作答。每节课至少一次 AI claim audit 可以自然放在改动判断或回顾阶段，审查一个具体主张，而不是为了格式另造长题。

下一次陪练先读本文件、对应课次、Summer 最新 session record 与 progress；找出上次停止点，从下一小闭环继续。若个人自述仍待填写，保留这个事实，不猜测已有能力；本授课方式已明确，不因表格未填就反复要求重新选择学习模式。
